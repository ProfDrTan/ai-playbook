The AI Trading Lab

A broker-agnostic, agent-driven trading bot, built in the open — including every wrong turn. Documented at the point of confirmed reality, not reconstructed afterward.

LIVE — 2026-07-29

01. Objective

What this project is actually trying to be.

A resilient, unattended trading bot covering both SPX options income and NQ/ES futures, with two hard constraints: no new recurring brokerage fees, and reuse of the agent work already proven in the CP3405 market intelligence pipeline (Almanac, Macro, Technical, LLM synthesis) rather than rebuilding it. A Fundamental Agent was added as a fourth signal — hard macro data (FRED) plus LLM-synthesized earnings tone, deliberately avoiding a paid earnings feed.

The architecture is broker-agnostic on purpose: an ExecutionAdapter interface sits between all decision logic and any specific broker, so the platform underneath (IBKR today, possibly Tiger Brokers or Moomoo later) can change without touching the agents or the scoring engine.

03. The Broker Shootout

Why IBKR, and why not the others — kept explicit so nobody re-litigates it from scratch.

PlatformVerdictWhy
TradierRejectedClean REST for options, but futures route through a separate Tradier Futures entity via CQG/Rithmic — not the same API. $10-35/mo subscription for commission-free options fails the no-fee objective outright.
IGRejectedUK/international CFD broker — trades CFDs on the underlying, not the actual CME-listed futures contract.
SchwabUnresolvedFree API, but futures support reads as market-data access only in available docs — order placement for NQ/ES never confirmed. Worth a direct question to Schwab, not assumed either way.
tastytradeSecond look candidateCovers equities/options/futures/crypto in one API, but tighter rate limits (~60 req/min) and API fee structure not independently confirmed.
MoomooWatchingConfirmed CME futures support, free API — but requires a persistent local gateway process (OpenD), same friction class as IBKR.
Tiger BrokersWatching closelyFree API, confirmed futures support, RSA key-signed requests — no persistent gateway, no per-request push-notification 2FA. Possibly superior to IBKR for unattended operation; untested in practice.
IBKRChosenOnly platform with confirmed free native execution of both options and futures in one already-funded account. Known cost: a headless Client Portal Gateway plus an estimated (not guaranteed) periodic manual 2FA touch.

05. Commandments

Written the moment each failure was confirmed, not reconstructed for effect.

2026-07-29 — COMMANDMENT #1
Thou shalt verify which account a connector is bound to before trusting a single tool call. A browser screenshot confirming a paper-account login proved nothing about which account an AI connector's tool calls were actually hitting — they turned out to be two entirely independent credentials. The connector had been silently resolving to the live account (U10500387) the whole time. The fix: call a read-only account-identity check (net liquidation value, account ID) before any trade-placing tool call, every time, not just once at setup.
2026-07-29 — COMMANDMENT #2
Thou shalt not assume a "reconnect" fixes what a settings toggle can't. Claude cannot log into a third-party service on a person's behalf — that boundary is deliberate, not a missing feature. Confirmed directly against Anthropic's own support documentation: connectors support one bound account per service today; multi-account support is requested but not shipped. The fix: when paper access is genuinely needed, disconnect and reconnect the credential itself with paper login — a real, if blunt, working path, once the actual constraint is named instead of guessed at.
2026-07-29 — COMMANDMENT #3
Thou shalt check the actual calendar before quoting a strike price. A live SPX bull put spread recommendation was generated using a generic "SPX market today" news search. It missed that the FOMC rate decision and four separate mega-cap earnings reports (MSFT, META, AAPL, AMZN) all landed inside the trade's 2-day holding window — a materially different risk picture than what was presented. The Fundamental Agent exists specifically to catch this and wasn't actually called. The pattern: a safeguard that exists in the codebase but isn't wired into the live decision path provides exactly zero protection. Fixing the wiring is now the top priority for the next session.
2026-07-29 — COMMANDMENT #4
Thou shalt not create a second order instruction without checking for the first. Two near-identical order instructions for the same spread ended up live simultaneously, caught only by looking directly at the IBKR Orders screen. The fix: ExecutionAdapter.get_open_orders() added, with a same-contract/same-side duplicate check now run inside place_order() before any submission — a safety net, not a mathematically perfect guarantee, but it catches the exact failure mode observed tonight.
