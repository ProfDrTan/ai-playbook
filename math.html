1CIA triad: confidentiality, integrity, availability.
Q1 Someone changes your grade but you can still log in. Which of C, I, A broke?
Integrity. The data was altered without authorisation; you could still reach the system (availability) and nothing was disclosed to you.
Q2 A hacker floods the student portal so nobody can log in during exam week. Which CIA element is hit?
Availability. Nothing was read or changed — legitimate users simply cannot get timely access.
Q3 An intruder reads every student’s grades but changes nothing. Which element, and is the system still ‘compromised’?
Confidentiality — and yes, it is compromised. Breaking any one of C, I or A is enough; all three must hold for the system to be secure.
\(\text{Secure} \iff C \wedge I \wedge A\)
Secure if and only if confidentiality AND integrity AND availability all hold.

1Authenticity: users are who they say they are, and every input comes from a trusted source.
Q1 Is a correct password enough to prove authenticity?
Not fully. Authenticity means the user is who they claim AND every input comes from a trusted source; a stolen password passes the first check falsely.
Q2 A message claims to be from the registrar. What would you check to establish its authenticity?
That it truly came from the registrar (a trusted source) — e.g. a verified signature — not merely that it arrived intact. Intact alone is integrity.
Q3 Integrity vs authenticity: a file arrives unchanged from an unknown sender. Which property do you have?
Integrity only. Unchanged ≠ trusted origin; authenticity needs proof of who sent it.
Q4 Fill the blank: ‘______ is verifying users are who they say they are and that inputs come from a trusted source.’ Why not accountability?
Authenticity. Accountability is tracing actions back to an entity after the fact — it doesn’t verify identity or source up front.
\(\text{Auth} = \text{who}(u)=\text{claimed}\ \wedge\ \text{src}(x)\in\text{Trusted}\)
Authentic means the user is who they claim AND the input came from a trusted source.

1Access control: preventing unauthorised use of a resource.
Q1 You are logged in. What stops you opening the payroll file?
Access control — the policy that decides what an identified user may use. Logging in (authentication) only proved who you are.
Q2 Authentication vs access control: which happens first, and what does each answer?
Authentication first (‘who are you?’), then access control (‘what may you do?’). Access control is the prevention of unauthorised use of a resource.
Q3 A cleaner’s swipe card opens the server room. Which security service failed?
Access control — the person is identified correctly, but the policy wrongly allows use of a resource they are not authorised for.
Q4 Is ‘preventing unauthorised use of a resource’ the same as confidentiality?
No. Confidentiality stops disclosure of information; access control governs any use (read, write, execute, enter) of any resource.
\(\text{allow}(s,o,a) \iff (s,o,a) \in \text{Policy}\)
Subject s may do action a on object o only if that triple is in the policy.

1Passive attacks watch; active attacks change or disrupt.
Q1 Is reading someone’s Wi-Fi traffic passive or active? What about replaying it?
Reading = passive (nothing changes). Replaying = active (it injects traffic and alters what the system receives).
Q2 Why are passive attacks said to be ‘hard to detect but easy to prevent’?
Nothing is altered, so there is no trace; but encryption makes the captured traffic useless.
Q3 ‘______ attacks attempt to alter system resources or affect their operation.’ Give one example.
Active — e.g. modification, masquerade, replay or denial of service.
\(\text{passive: } m'=m \qquad \text{active: } m'\neq m\)
Passive: the message arrives unchanged. Active: what arrives is not what was sent.

1Server-side web attacks hit the application on the server (SQL, XML injection, XSS); network attacks like ARP spoofing do not.
Q1 Which one is the odd one out: SQL injection, XSS, ARP spoofing, directory traversal?
ARP spoofing — it attacks the local network (layer 2), not the web application on the server.
Q2 Why does SQL injection count as server-side?
The malicious input is executed by the server’s database through the web app — the server is the target.
Q3 Directory traversal (../../etc/passwd): what is the attacker reaching for?
Files on the web server outside the web root — a server-side attack on the application’s file handling.
Q4 Drive-by download vs XML injection: which is NOT server-side?
Drive-by download — it infects the visitor’s browser/PC (client side). XML injection targets the server’s XML processing.
Q5 Why is web server software a particular focus of the attack surface?
It is exposed to everyone on the internet, so every input it accepts is a door an attacker can try.

1Privilege escalation: horizontal = sideways to a peer’s functions; vertical = up to higher privilege.
Q1 A student opens another student’s account. Horizontal or vertical?
Horizontal — same privilege level, sideways into a peer’s functions.
Q2 A student account gains lecturer powers to edit marks. Which type?
Vertical — moving up to a higher privilege level.
Q3 Define horizontal privilege escalation in one line.
A user with restricted privileges accesses the restricted functions of a similar user.
Q4 Transitive access vs privilege escalation — same thing?
No. Transitive access is gaining access through a trusted intermediary (A trusts B, B trusts C); escalation is about a user’s own privilege level being exceeded.
\(\text{horiz: } L(u')=L(u) \qquad \text{vert: } L(u')>L(u)\)
Horizontal: same privilege level, different user. Vertical: a higher level.

1Defence in depth (onion model): layers, so one failure is not a breach.
Q1 Three layers each stop 90% of attacks. What fraction gets all the way in?
0.1 × 0.1 × 0.1 = 0.001 — one in a thousand. That is why layers matter.
Q2 What steps decide which layers you need?
Identify assets and their value, assess threats and risks, then place controls per layer (perimeter, network, host, application, data) and decide how layers are separated (firewalls, DMZ, VLANs).
Q3 ‘More layers always means more security.’ Agree?
Not automatically — layers must be independent. If one stolen password opens every layer, the layers fail together.
\(P(\text{breach}) = \prod_{i=1}^{L} p_i \quad (0.1^3 = 0.001)\)
The chance of a breach is the product of each layer’s failure chance: one in a thousand here.

1Malware: name two types (e.g. virus, worm) and how to mitigate each.
Q1 What does a worm do that a virus cannot?
Spread by itself across the network. A virus needs a host file and usually a user action to run.

2Switch attacks: MAC flooding, MAC impersonation, ARP poisoning, port mirroring, network tap.
Q1 Fill a switch’s address table with fake MACs. What does the switch turn into, and what’s the defence?
A hub — it floods every frame to every port, so the attacker can sniff. Defence: port security limiting MACs per port.
\(|\text{MAC table}| > \text{capacity} \Rightarrow \text{switch} \to \text{hub}\)
Once the address table overflows, the switch behaves like a hub and broadcasts everything.
W2-2
2ARP poisoning redirects traffic by forging IP-to-MAC answers; it can chain into DNS cache poisoning.
Q1 If you sit between a victim and the gateway via ARP poisoning, what else can you fake?
DNS replies — so the victim is sent to a fake site even when typing the right name (ARP → DNS cache poisoning).
Q2 Why does ARP poisoning work at all?
ARP has no authentication; devices accept unsolicited replies and overwrite their IP-to-MAC cache.
\(\text{ARP}(IP_{gw}) \mapsto MAC_{attacker}\)
The gateway’s IP address now maps to the attacker’s MAC address.

2Broadcast storms come from loops; loop protection (e.g. STP) prevents them.
Q1 Two cables between the same two switches. What happens to one broadcast?
It loops forever and multiplies — a broadcast storm that can bring the network down.
Q2 Which feature prevents broadcast storms, and how?
Loop protection (e.g. Spanning Tree Protocol), which detects redundant paths and blocks one so no loop forms.

2Proxy server: processes requests on behalf of the user.
Q1 Name one thing a proxy can do that a router cannot.
Inspect and cache application requests (e.g. web pages) and filter by content — it acts on behalf of the user.
Q2 Fill the blank: ‘A ______ processes requests on behalf of the user.’ Why not a load balancer?
Proxy server. A load balancer spreads incoming requests across servers; it does not act on the user’s behalf.
Q3 How can a proxy increase speed AND reduce cost at once?
Caching: repeated requests are served locally — faster responses and less internet bandwidth paid for.
Q4 Does a proxy hide the user from the destination server?
Yes — the server sees the proxy’s address, not the user’s.
Q5 Proxy vs firewall: which reads inside the web request?
The proxy (application level). A basic packet-filtering firewall only looks at headers.
Q6 ‘All are correct’ is offered for a proxy’s advantages. When is that the safe pick?
Only if every option is true. Here the true advantage is increased speed with reduced cost — check the options, don’t default to ‘all’.
\(\text{Client} \rightarrow \text{Proxy} \rightarrow \text{Server}\)
The client talks to the proxy, and the proxy talks to the server on its behalf.

2VPN: use an unsecured public network as if it were a secure private one.
Q1 Café Wi-Fi: what does a VPN hide from the café owner?
The contents and real destination of your traffic — it is encrypted inside a tunnel to the VPN endpoint.
Q2 VPN vs VLAN — which lets you use a public network as if it were private?
VPN. A VLAN logically separates a local network; it does not secure traffic over the public internet.
\(\text{tunnel} = E_k(\text{packet}) \text{ over the public net}\)
The whole packet travels encrypted inside a tunnel across the public network.

2DMZ, flood guard, port security, NAC: the switch-and-perimeter toolkit.
Q1 Where would you put the public web server, and why not inside?
In the DMZ — so if it is breached, the attacker is still outside the internal network.
Q2 What is a flood guard protecting against?
Floods of traffic (e.g. SYN or MAC floods) — it limits rates so the device stays available.
Q3 Port security: what does it restrict?
Which/how many MAC addresses may use a switch port, blocking MAC flooding and unknown devices.
Q4 NAC checks three things before letting a laptop in. Name them.
Who the user is (authentication), what they may access (authorisation), and whether the device is healthy (patched, antivirus).

3Three classes of intruder: masquerader, misfeasor, clandestine user.
Q1 An employee misuses access they genuinely have. Which class?
Misfeasor — legitimate user, abusing or exceeding their access.
Q2 Masquerader vs clandestine user?

3Stateful inspection firewall remembers connection state; packet filter judges each packet alone.
Q1 Why can a stateful firewall reject a reply nobody asked for?
It remembers outgoing connections; an ‘answer’ with no matching request is dropped.
Q2 Which firewall examines headers at all layers and remembers relationships between packets?
Stateful inspection firewall. A packet filter judges each packet alone; a circuit-level gateway works at session level.

A packet filter decides from the packet alone; a stateful firewall also uses connection state.

3Firewall default policy and the bastion host.
Q1 Default deny or default allow: which would a bank choose?
Default deny (discard) — anything not explicitly allowed is blocked. Safer, at the cost of convenience.
Q2 What is a bastion host?
A hardened system that is a critical strong point in the network’s security, exposed to attack and built to withstand it.
\(\forall t:\ \text{deny}(t)\ \text{unless}\ t \in \text{Allowed}\)
For all traffic: deny it unless it is explicitly allowed.

3Rule-based detection uses known attack patterns; anomaly detection flags departures from normal.
Q1 Rule-based or anomaly — which can catch a brand-new attack?
Anomaly detection — it flags departures from normal behaviour, even with no known pattern.
Q2 ‘A set of rules or attack patterns used to decide if behaviour is due to an intruder.’ Name it.
Rule-based detection.
Q3 Threshold detection: rule-based or anomaly?
Statistical anomaly — it counts events and alarms when a threshold for ‘normal’ is exceeded.
Q4 Biggest weakness of rule-based detection?
It misses attacks that match no existing rule (zero-days) until the rules are updated.
\(\text{rule: } x \in \text{Patterns} \qquad \text{anomaly: } |x-\mu| > k\sigma\)
Rule-based: x matches a known pattern. Anomaly: x is more than k standard deviations from normal.

3IDS outcomes: true/false positive, true/false negative.
Q1 Alarm rings, no intruder. What is that called?
A false positive.
Q2 The IDS correctly flags a real intrusion. Name the outcome.
True positive.
Q3 Which outcome is the most dangerous, and why?
False negative — a real intrusion goes unnoticed.
\(\text{TP} = \text{alarm} \wedge \text{intrusion} \qquad \text{FP} = \text{alarm} \wedge \neg\text{intrusion}\)
True positive: alarm and a real intrusion. False positive: alarm with no intrusion.

3Salt and pepper: stop identical passwords giving identical hashes, and defeat precomputed tables.
Q1 Two users both pick ‘password123’. Without salt, what does the attacker see?
Identical hashes — crack one, crack both, and precomputed rainbow tables work.
Q2 Where are salt and pepper stored?
Salt: stored with the hash, per user (not secret). Pepper: a secret kept separately (e.g. in application config), not in the database.
Q3 How should the system initialise a user’s salt?
Generate a random number when the password is first set/loaded — never ask the user for it.
\(\text{stored} = \big(s,\ H(s \,\|\, pw \,\|\, p)\big),\ s \text{ random per user},\ p \text{ secret}\)
Store the salt s and the hash of salt, password and pepper. The salt is random per user; the pepper is kept secret.

4Correctness: with the same key on both sides, decryption undoes encryption.
Q1 If decryption did not give m back, what would be broken?
The scheme’s correctness — the receiver could not recover the message, so it is not a usable cipher, however ‘secure’.
\(\forall k,\forall m:\ D_k(E_k(m)) = m\)
For every key k and every message m, decrypting with k what was encrypted with k gives back m.

4Kerckhoffs: the machines E and D are public; only the key k is secret.
Q1 ‘AES is safe because nobody knows how it works.’ True?
False. AES is fully public; its security rests only on the secrecy of the key.
Q2 Symmetric encryption’s security depends on the secrecy of what?
The key — not the algorithm, not the plaintext.
Q3 Why publish the algorithm at all?
So experts worldwide can attack it; surviving public scrutiny is what earns trust. Hidden algorithms leak and then fail.
Q4 If the key is stolen but the algorithm is strong, are you safe?
No. With the key, anyone can decrypt — the algorithm offers no protection.
\(c = E_k(m),\quad E, D\ \text{public},\ k\ \text{secret}\)
c equals E-sub-k of m. E and D are public; only k is secret.

4Every cipher has a coordinate on three independent axes.
Q1 Where does AES sit on the three axes?
Substitution and permutation, one key (symmetric), block.
Q2 Sender and receiver share one key. What is the scheme called?
Symmetric (also conventional, secret-key, single-key) encryption.
Q3 A real-time sensor streams data continuously. Block or stream cipher, and why?
Stream — it encrypts bit by bit with low latency and no waiting to fill blocks; but never reuse the key/IV.
Q4 Caesar cipher on the three axes?
Substitution, one key (symmetric), stream-like (letter by letter).
\(\{\text{Sub},\text{Trans}\} \times \{1\text{ key}, 2\text{ keys}\} \times \{\text{Block},\text{Stream}\}\)
Every cipher is a choice of substitution or transposition, times one key or two, times block or stream.

4Brute force: on average you search half the keyspace. DES has 256 keys.
Q1 Why only half the keyspace on average?
The right key is equally likely to be anywhere, so on average you find it halfway through: |K|/2.
\(\mathbb{E}[\text{tries}] = \tfrac{|\mathcal{K}|}{2} = 2^{n-1}\)
The expected number of tries is the size of the keyspace over two, which is two to the n minus one.
W4-3
4Reusing a stream key cancels the keystream and leaks both messages.
Q1 WEP used a strong cipher. So why did it fall?
Keystream reuse — short, repeating IVs meant c ⊕ c′ = m ⊕ m′, leaking plaintext. The key management failed, not RC4.
\(c \oplus c' = (m \oplus z) \oplus (m' \oplus z) = m \oplus m'\)
c XOR c-prime equals m XOR m-prime: the keystream z cancels out.
—
4CTR mode turns a block cipher into a stream cipher (so does CFB).
Q1 Why can CTR encrypt block 100 before block 1?
Each block uses E_k(counter_i), which depends on nothing but i — so blocks are independent and parallel. CTR and CFB both turn a block cipher into a stream cipher.
\(C_i = P_i \oplus E_k(\text{ctr}_i)\)
Ciphertext block i equals plaintext block i XOR the encryption of counter i.
W4-2
5Successful decryption does not prove the message is unaltered.
Q1 I swapped two encrypted blocks and it still decrypted. Is the message authentic?
No. Symmetric encryption alone is not sufficient for authentication — False. You need a tag (MAC/hash).
\(D_k(c') \text{ decrypts} \;\not\Rightarrow\; m' = m\)
That c-prime decrypts does not imply that m-prime equals m.
D-21
5Two tag types: a hash has one input; a MAC has two (key + message).
Q1 If a hash needs no key, how can it prove who sent the message?
On its own it can’t — protect it with a shared key, a private key, or a secret value; or use a MAC, which takes K and M.
\(MD = H(M) \quad\text{vs}\quad T = F(K, M)\)
The digest equals H of M, versus the tag equals F of K and M.
D-2
5Any length in, fixed length out: reversible in principle, infeasible in practice.
Q1 If outputs are shorter than inputs, must collisions exist?
Yes (pigeonhole). So a secure hash is ‘reversible in principle but difficult’ — True.
\(H: \{0,1\}^{*} \rightarrow \{0,1\}^{n}\)
H maps bit strings of any length to bit strings of length n.
W5-5
5XOR hash: order doesn’t matter, so swapping blocks gives the same hash — a collision.
Q1 Give me a different message with the same XOR hash as 0100 1011 1101 0011.
1101 0011 0100 1011 — swap the blocks; XOR doesn’t care about order. Both hash to 1001 1000.
Q2 What does 0100 1011 ⊕ 1101 0011 give?
1001 1000 — bits that differ give 1, bits that match give 0.
Q3 Does 0001 1101 0110 1011 collide with it?
No: 0001 1101 ⊕ 0110 1011 = 0111 0110 ≠ 1001 1000.
Q4 Name a second trick (besides swapping) that makes an XOR-hash collision.
Flip the same bit position in two blocks — the two flips cancel. E.g. 1100 1011 0101 0011.
\(h = B_1 \oplus B_2 \oplus \cdots \oplus B_m,\quad B_1 \oplus B_2 = B_2 \oplus B_1\)
h equals B-one XOR B-two XOR … B-m; and B-one XOR B-two equals B-two XOR B-one.

5Birthday paradox: finding any collision costs far less than matching a given hash.
Q1 How many people before two probably share a birthday?
23 (≈50.7%). Matching one specific birthday needs about 253 — collisions are far cheaper than preimages.
\(1 - \prod_{i=0}^{22}\tfrac{365-i}{365} \approx 0.507;\quad 2^{n/2} \ll 2^{n}\)
One minus the product, for i from 0 to 22, of 365 minus i over 365, is about 0.507; and two to the n over two is far smaller than two to the n.

5HMAC: hash twice, with the key disguised two different ways.
Q1 Why not just hash the key and the message once?
Simple key+message hashes are open to attacks like length extension; HMAC’s nested double hash with ipad/opad closes them.
\(H\big((K^{+}\!\oplus \text{opad}) \,\|\, H((K^{+}\!\oplus \text{ipad}) \,\|\, M)\big)\)
H of: K-plus XOR opad, joined to H of K-plus XOR ipad joined to M.

5Public-key: what one key locks, only the other unlocks. Which key locks decides what you get.
Q1 Alice wants only Bob to read it. Whose key, which one?
Bob’s public key — only Bob’s private key decrypts it.
Q2 What is the most important use of the private key: generate or verify signatures?
Generate digital signatures. Verifying uses the public key.
\(D_{sk}(E_{pk}(m)) = m\)
Decrypting with the secret key what was encrypted with the public key gives back m.

5Diffie-Hellman: both sides reach the same key without sending it — but nothing proves who is on the other end.
Q1 Can an attacker in the middle run two exchanges at once?
Yes — Diffie-Hellman authenticates no one, so it does NOT avoid man-in-the-middle (False). Add certificates or signatures.
\(K = (\alpha^{b})^{a} = (\alpha^{a})^{b} = \alpha^{ab} \bmod q\)
K equals alpha to the b, raised to the a, equals alpha to the a, raised to the b, equals alpha to the a-b, mod q.
W5-3
5RSA: e and d are inverses modulo φ(n). Example: 7 × 23 = 161 ≡ 1 (mod 160).
Q1 Factor 187. Now factor a 600-digit number.
187 = 11 × 17 in seconds; the large one is infeasible. RSA’s security rests on that gap.
\(ed \equiv 1 \pmod{\varphi(n)},\quad C = M^{e},\ M = C^{d} \bmod n\)
e times d is congruent to 1 modulo phi of n; C equals M to the e, and M equals C to the d, mod n.

5Digital signature: sign the hash with the private key; anyone checks with the public key.
Q1 What does a signature give that a MAC cannot?
Non-repudiation — only the signer’s private key could have made it; with a MAC, either key holder could.
Q2 Encrypting a hash with your private key is essentially what?
A digital signature — the main use of the private key.
\(S = H(M)^{d} \bmod n,\quad \text{accept iff } S^{e} \bmod n = H(M)\)
S equals H of M to the d, mod n; accept if and only if S to the e, mod n, equals H of M.

6Symmetric key count explodes: every pair needs its own key.
Q1 15 people, one key per pair. How many keys?
15 × 14 / 2 = 105.
Q2 Why not 15 × 15 = 225?
You don’t need a key with yourself (−15), and the A–B key is the same as B–A (÷2).
\(N = \binom{n}{2} = \frac{n(n-1)}{2} \qquad n=15 \Rightarrow 105\)
N equals n choose 2, which is n times n minus one over two; fifteen people need 105 keys.

6Key hierarchy: a permanent key is used to distribute short-lived session keys.
Q1 Why not use the permanent key for every message?
Each use exposes it to analysis; short-lived session keys limit the damage if one is broken.
Q2 Fill: ‘A ______ key is used to distribute ______ keys.’
Permanent, session.
Q3 Who issues the session key in a symmetric scheme?
The Key Distribution Centre (KDC), encrypted under each party’s permanent (master) key.
Q4 A session key leaks. What is exposed?
Only that session’s traffic — the permanent key and other sessions stay safe.
\(K_{\text{session}} \xrightarrow{\ E_{K_{\text{perm}}}\ } \text{each party}\)
The session key travels encrypted under each party’s permanent key.

6Kerberos tickets carry a timestamp and lifetime, and nonces prove freshness — both stop replay.
Q1 I copy your ticket today. Why can’t I use it next week?
Its timestamp and lifetime expire — this stops replay attacks.
Q2 What does a nonce guarantee in a Kerberos v5 exchange?
Freshness — the response matches this request, not one replayed by an attacker.
Q3 Name another way to protect tickets besides lifetime.
Encryption under the service’s key, plus an authenticator (timestamp, client address) only the real client can produce.
Q4 Why does the TGT exist at all?
So you authenticate once with the AS; the TGS then issues service tickets without re-sending your password.
\(\text{valid} \iff TS \le t_{\text{now}} \le TS + \text{Lifetime}\)
A ticket is valid only if the current time lies between its timestamp and timestamp plus lifetime.

6User authentication: identify, then verify — by something you know, have, are (static), or do (dynamic).
Q1 Fingerprint and typing rhythm: which is ‘are’ and which is ‘do’?
Fingerprint = something you are (static biometric); typing rhythm = something you do (dynamic biometric).

\(\text{factors} \in \{\text{know},\ \text{have},\ \text{are},\ \text{do}\}\)
The four means: something you know, have, are, or do.

6Single sign-on: log in once at an identity provider; each app trusts its assertion.
Q1 Google is down. What happens to every app that uses ‘Sign in with Google’?
Nobody can log in to any of them — SSO’s single point of failure.
Q2 Walk the SSO steps.
User opens App A → redirected to the identity provider → logs in once → IdP returns a signed token → App A trusts it; App B reuses the same session.
