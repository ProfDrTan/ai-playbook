Discord Setup Cheat Sheet

How the CP3405 Discord server, roles, and monitoring bot actually get set up — written from the TR3 build session, 13–14 Sep 2026.

1. Create a New Server (per trimester)

Left sidebar → green "+" at the bottom → Create My Own → any purpose answer → name it clearly, e.g. "CP3405 TR3 2026" → Create.

2. Create Team Channels

Hover Text Channels → "+" → type the name directly (e.g. team-1) → Create Channel. Repeat per team.

3. Lock a Channel to One Role (Private Channel)

Right-click the channel → Edit Channel → Permissions tab → toggle "Private Channel" ON. This automatically denies @everyone. Then click "Add members or roles" → type the role name → select it. Confirm it now shows under "Roles" on the left panel.
Gotcha: the role search dropdown sometimes doesn't show a role that should be there (scroll/render glitch). Fix: type the exact role name directly into the search box instead of scrolling — it appears once typed.
Note: this Private Channel toggle is simpler than manually editing "Advanced permissions" → General Channel Permissions for @everyone. Use the toggle method first; only fall back to Advanced permissions if the toggle isn't available for some reason.

4. Create Roles

Server name (top-left) → Server Settings → Roles → Create Role, once per team. No special permissions needed on the role itself — the channel lock (step 3) is what actually restricts access.

5. Generate a Permanent Invite Link

Right-click server name → Invite People → "Edit invite link" (small text near the bottom) → set Expire After: Never, Max Uses: No limit → Copy Link.

6. Invite the Monitoring Bot ("Dr Tan -Private")

Application ID: 1511174177367789748

Invite URL pattern:
https://discord.com/api/oauth2/authorize?client_id=1511174177367789748&permissions=66560&scope=bot

Open it → click "Keep Scrolling..." (permissions list) → select the correct server from the dropdown → Authorize → complete captcha if prompted.
Gotcha — check this every time: the success screen says "Dr Tan -Private has been authorized and added to [server name]." If an old server (e.g. a prior trimester's) shows up instead of the current one, the dropdown selection didn't take — redo it and read the success message carefully before moving on.
Permissions number explained: 66560 = View Channel (1024) + Read Message History (65536). Enough for read-only monitoring, nothing else.

7. Retargeting the Monitor for a New Trimester

The bot's actual logic lives in a private GitHub repo: ProfDrTan/dt3-monitor, file dt3_discord_monitor_actions.py, running automatically via GitHub Actions (.github/workflows/monitor.yml) — no PC or hosting needed, it runs on GitHub's own servers.

To point it at a new trimester's channels:
  1. Invite the bot to the new server (step 6 above)
  2. Get each team channel's ID: User Settings → Advanced → enable Developer Mode → right-click each channel → Copy Channel ID
  3. Update the CHANNELS = {...} dictionary near the top of dt3_discord_monitor_actions.py with the new IDs, keeping the same team-name keys
  4. Push. The existing hourly schedule picks it up automatically — nothing else to configure.
Also in that script: a separate "spotlight" tracker can be pointed at one specific student's personal GitHub repo for closer scrutiny (used on sinder38/Georgii in TR2). Update TEAM1_REPO near the top if a new trimester needs the same targeted tracking — leave it pointed at nothing/disabled if nobody warrants it yet.

8. Restricting Access — The Concept

A role is just a tag Discord gives a member. A channel locked to a role is invisible to anyone without that tag — not just "hidden by convention," genuinely not viewable. New members with no role at all only see whatever's left open to @everyone (typically just #general), so that channel functions as a real waiting room once the team channels are locked.
